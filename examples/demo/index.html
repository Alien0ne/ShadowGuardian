Lesson 4: How a hash table resolves collisions

A hash table stores each key in a slot chosen by a hash function. Two different keys can land in the same slot, and the table needs a rule for what happens next. The two common rules are separate chaining and open addressing.

With separate chaining every slot holds a small list. A colliding key is appended to the list of its slot, and a lookup scans that list. The table keeps working when it is over-full, at the cost of following pointers.

def put(table, key, value):
    slot = hash(key) % len(table)
    for entry in table[slot]:
        if entry[0] == key:
            entry[1] = value
            return
    table[slot].append([key, value])

With open addressing a colliding key moves on to another slot in the same array, following a probe sequence. Lookups stay inside one block of memory, which is fast, but the table must be resized before it fills up.

Whichever rule is used, performance depends on the load factor: the number of stored keys divided by the number of slots. Most implementations resize when it passes a threshold between one half and three quarters.
